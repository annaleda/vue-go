# 01 — Go

[← Indice](../README.md#documentazione) · [Vue →](02-vue.md)

Go arrivando da Java. Non è un manuale: sono le cose che cambiano il modo di
scrivere, spiegate sul codice di questo progetto.

---

## 1. Le differenze che si notano subito

| | Java | Go |
|---|---|---|
| Ereditarietà | classi, `extends` | **non esiste**: composizione e interfacce |
| Interfacce | si dichiarano con `implements` | **implicite**: se hai i metodi giusti, la implementi |
| Errori | eccezioni, `try/catch` | **valori di ritorno**, si controllano a mano |
| Null | `null` ovunque | valori zero (`0`, `""`, `nil`) + `ok` esplicito |
| Concorrenza | thread, `ExecutorService` | **goroutine** e canali |
| Generici | dal 2004 | dal 2022 (1.18), usati con parsimonia |
| Dipendenze | Maven, centinaia di jar | standard library molto ricca |
| Avvio | JVM, secondi | binario nativo, millisecondi |

La conseguenza pratica più visibile è nelle dimensioni: i due servizi di
questo progetto stanno in **7 MB** di immagine Docker e partono in un istante.
Un equivalente Spring Boot parte da ~250 MB e qualche secondo.

---

## 2. Struct e tag JSON

Non ci sono classi. C'è la `struct`, che è solo dati.

```go
type Garanzia struct {
    Codice       string  `json:"codice"`
    Nome         string  `json:"nome"`
    PrezzoBase   float64 `json:"prezzoBase"`
    Obbligatoria bool    `json:"obbligatoria"`
}
```

Due regole che sorprendono chi arriva da Java:

**La maiuscola è la visibilità.** Un identificatore che inizia con la
maiuscola è esportato (pubblico), con la minuscola no. Non ci sono
`public`/`private`. E questo vale anche per l'encoder JSON: **un campo
minuscolo non viene serializzato**, perché la libreria non lo vede. È la
causa numero uno di "perché il mio JSON esce vuoto".

**I tag** dicono come si chiama il campo una volta serializzato. Senza,
avresti `{"Codice": ...}` con la maiuscola.

## 3. Gli errori sono valori

Questa è la differenza che cambia di più il modo di scrivere.

```go
prev, err := Calcola(req, garanzie)
if err != nil {
    // gestisci
    return
}
// qui prev è utilizzabile
```

Una funzione restituisce **due valori**: il risultato e l'errore. Non c'è
modo di ignorare l'errore per distrazione: se non lo assegni il compilatore
protesta, e se lo assegni ti sta lì davanti.

Il codice diventa più verboso, ma il percorso di errore è sempre visibile.
In Java un'eccezione può attraversare dieci livelli senza che si veda nulla.

### Wrapping e sentinelle

```go
var ErrValidazione = errors.New("richiesta non valida")

// più in basso:
return fmt.Errorf("%w: età fuori intervallo", ErrValidazione)
```

Il verbo `%w` **avvolge** l'errore mantenendone l'identità. Chi riceve può
chiedere "è un errore di validazione?" senza confrontare le stringhe:

```go
if errors.Is(err, ErrValidazione) {
    writeError(w, http.StatusBadRequest, err.Error())   // 400
    return
}
writeError(w, http.StatusInternalServerError, "...")    // 500
```

È il modo idiomatico di distinguere *"hai sbagliato tu"* da *"si è rotto
qualcosa"*, e in `quote-service/main.go` è proprio quello che decide se
rispondere 400 o 500.

## 4. Slice e mappe

```go
var catalogo = []Garanzia{ ... }              // slice: lista ordinata
perCodice := make(map[string]Garanzia, 10)    // mappa: chiave -> valore
```

Sulle mappe c'è un idioma da conoscere, il **"comma ok"**:

```go
g, ok := perCodice[codice]
if !ok {
    return fmt.Errorf("garanzia sconosciuta %q", codice)
}
```

Leggere una chiave assente **non è un errore**: restituisce il valore zero
del tipo. Se ti serve distinguere "assente" da "presente ma vuoto", il
secondo valore `ok` è l'unico modo. Dimenticarlo produce bug silenziosi.

## 5. Il server HTTP sta nella standard library

Non serve Spring, non serve un framework:

```go
mux := http.NewServeMux()
mux.HandleFunc("/api/v1/garanzie", handleGaranzie)

srv := &http.Server{
    Addr:         ":8080",
    Handler:      logging(mux),
    ReadTimeout:  5 * time.Second,
    WriteTimeout: 10 * time.Second,
}
srv.ListenAndServe()
```

Ogni handler ha sempre la stessa firma: dove scrivere, e cosa è stato chiesto.

```go
func handleGaranzie(w http.ResponseWriter, r *http.Request) {
    writeJSON(w, http.StatusOK, catalogo)
}
```

**I timeout non sono un dettaglio.** `http.Server` senza timeout accetta
connessioni che restano appese per sempre, e ogni connessione occupa una
goroutine. È uno dei modi più comuni di far cadere un servizio Go.

Stessa cosa lato client: `http.DefaultClient` **non ha timeout**. In
`catalog_client.go` infatti il client è costruito a mano:

```go
&http.Client{Timeout: 5 * time.Second}
```

### Middleware senza framework

Un middleware in Go è una funzione che prende un handler e ne restituisce
un altro:

```go
func logging(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        start := time.Now()
        next.ServeHTTP(w, r)
        log.Printf("%s %s (%s)", r.Method, r.URL.Path, time.Since(start))
    })
}
```

Si compongono annidandoli: `cors(logging(mux))`. Tutto qui — nessuna
annotazione, nessun contenitore di dipendenze.

## 6. Goroutine, canali, mutex

`go f()` esegue `f` in modo concorrente. Costa pochi kilobyte, non megabyte
come un thread: si possono averne centinaia di migliaia.

In `main.go` serve a non bloccare il programma principale:

```go
go func() {
    if err := srv.ListenAndServe(); err != nil && err != http.ErrServerClosed {
        log.Fatalf("errore del server: %v", err)
    }
}()

// il main resta libero di aspettare il segnale di spegnimento
stop := make(chan os.Signal, 1)
signal.Notify(stop, os.Interrupt, syscall.SIGTERM)
<-stop        // si blocca qui finché non arriva un segnale
```

`chan` è un canale: una coda tipizzata con cui le goroutine si parlano.
`<-stop` legge dal canale e blocca finché non c'è qualcosa da leggere.

### Il mutex, e perché serve

Il server HTTP gestisce **ogni richiesta in una goroutine diversa**. Quindi
qualunque dato condiviso è toccato da più goroutine insieme. In
`catalog_client.go` la cache è protetta così:

```go
type CatalogClient struct {
    mu    sync.RWMutex
    cache []Garanzia
}

c.mu.RLock()          // lettura: più goroutine insieme
...
c.mu.RUnlock()

c.mu.Lock()           // scrittura: una sola per volta
...
c.mu.Unlock()
```

`RWMutex` distingue lettori e scrittori: tante letture concorrenti, una
scrittura esclusiva. Senza, si ha una *data race*: comportamento non definito,
che si manifesta in produzione sotto carico e non in sviluppo.

> Go ha uno strumento per trovarle: `go test -race ./...` e `go run -race .`
> Vale la pena usarlo su qualunque codice concorrente.

## 7. `defer` e `context`

**`defer`** rimanda l'esecuzione alla fine della funzione, qualunque sia
l'uscita:

```go
resp, err := c.http.Do(req)
if err != nil { return nil, err }
defer resp.Body.Close()
```

È l'equivalente di `finally`, ma si scrive **accanto** all'operazione che
apre la risorsa, non venti righe più in basso. Dimenticare `resp.Body.Close()`
è la causa più comune di connessioni HTTP perse in Go.

**`context`** propaga scadenze e annullamenti attraverso le chiamate:

```go
func (c *CatalogClient) Garanzie(ctx context.Context) ([]Garanzia, error) {
    req, _ := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
    ...
}
```

In `quote-service` si passa `r.Context()`, cioè il context della richiesta
HTTP in arrivo. Se il browser chiude la connessione, **anche la chiamata a
`catalog-service` viene interrotta**: non si spreca lavoro per una risposta
che nessuno leggerà. Per convenzione è sempre il primo parametro.

## 8. I test

Nessuna libreria, nessuna annotazione. File che finisce per `_test.go`,
funzione che inizia per `Test`:

```go
func TestClassePeggioreCostaDiPiu(t *testing.T) {
    ...
    if pPeggiore.Totale <= pMigliore.Totale {
        t.Errorf("classe 18 (%v) dovrebbe costare più di classe 1 (%v)",
            pPeggiore.Totale, pMigliore.Totale)
    }
}
```

`t.Errorf` segnala e continua, `t.Fatalf` segnala e ferma il test.

Molto usati i **test tabellari**: un caso per riga, un solo corpo.

```go
casi := []struct {
    nome     string
    modifica func(*RichiestaPreventivo)
}{
    {"età troppo bassa", func(r *RichiestaPreventivo) { r.EtaConducente = 15 }},
    {"provincia non valida", func(r *RichiestaPreventivo) { r.Provincia = "BOL" }},
}

for _, c := range casi {
    t.Run(c.nome, func(t *testing.T) { ... })
}
```

`t.Run` crea un sottotest con nome proprio: nell'output si vede esattamente
quale caso è fallito. Provalo:

```bash
cd services/quote-service && go test -v ./...
```

## 9. Dove guardare nel codice

| Concetto | File |
|---|---|
| struct, tag JSON, slice | `catalog-service/main.go` |
| server HTTP, middleware, spegnimento pulito | `catalog-service/main.go` |
| errori come valori, `%w`, `errors.Is` | `quote-service/quote.go` |
| mappe e "comma ok" | `quote-service/quote.go` |
| client HTTP, `context`, `defer` | `quote-service/catalog_client.go` |
| mutex e cache concorrente | `quote-service/catalog_client.go` |
| dipendenze in una struct invece che globali | `quote-service/main.go` |
| test tabellari | `quote-service/quote_test.go` |

## 10. Comandi

```bash
go run .              # compila ed esegue
go build -o app .     # produce il binario
go test ./...         # esegue i test
go test -race ./...   # cerca le data race
go vet ./...          # analisi statica: trova errori comuni
gofmt -l .            # elenca i file non formattati
```

`gofmt` merita una nota: la formattazione in Go **non è negoziabile**. Non
esistono discussioni su tab o spazi, perché c'è un solo formato e lo impone
lo strumento. È una delle cose che si apprezzano di più.
